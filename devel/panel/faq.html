    Implementation Choices¶

    While the implementation of the panel estimators is similar to Stata, there are some differenced worth noting.

    Small-sample Adjustments¶

    The fit method of every panel estimator has debiased=True as its default. This is the case for PooledOLS, PanelOLS, BetweenOLS, FirstDifferenceOLS, RandomEffects and FamaMacBeth. The IV estimators, including AbsorbingLS, have debiased=False.

    With debiased=True, the covariance is scaled by \(n/(n-k)\), where \(n\) is the number of observations and \(k\) is the number of regressors. The p-values and the confidence intervals of the parameters use a Student’s t distribution with the residual degrees of freedom, and the joint tests of significance use an F distribution. With debiased=False the covariance is not scaled by this factor, and the normal and \(\chi^2\) distributions are used. PanelOLS is an exception, see Counting the Effects.

    The clustered covariance, cov_type="clustered", has a second adjustment, which is for the number of clusters. group_debias=True multiplies the covariance by \(g/(g-1) \times (n-1)/n\), where \(g\) is the number of distinct clusters. With two-way clustering, it is applied to each of the three one-way covariances that are combined. The default is group_debias=False.

    Matching Stata¶

    Stata’s regress with vce(cluster) scales the clustered covariance by \(g/(g-1) \times (n-1)/(n-k)\). This is debiased=True, which is the default, together with group_debias=True.

    from linearmodels import PooledOLS
from linearmodels.datasets import wage_panel

data = wage_panel.load().set_index(["nr", "year"])
mod = PooledOLS.from_formula("lwage ~ 1 + expersq + married + union", data)
res = mod.fit(
    cov_type="clustered", cluster_entity=True, debiased=True, group_debias=True
)

    The standard errors agree with those of the same regression in R, sandwich::vcovCL(model, cluster = ~nr, type = "HC1", cadjust = TRUE), which uses the same formula. The default, group_debias=False, gives smaller standard errors, which matters when there are few clusters. If the clusters are defined by a variable with two values, the ratio of the default standard errors to those of Stata is \(\sqrt{n(g-1)/((n-1)g)}\), which is close to \(\sqrt{1/2}\), or 71%, if \(g=2\) and \(n\) is large. Few clusters, such as two, give unreliable standard errors whichever adjustment is used. The tests of the package that compare clustered covariances with Stata’s regress and xtreg use debiased=True and group_debias=True.

    xtreg and regress with a dummy variable for each entity count the effects differently when the effects are nested in the clusters, so expect differences if you compare the estimators with both commands.

    Counting the Effects¶

    PanelOLS counts the effects that it estimates in its degrees of freedom, which is the extra_df of its covariance estimators. If \(d\) is the number of effects, the covariance is scaled by \(n/(n-d-k)\) if debiased is True, and by \(n/(n-d)\) if it is False, so that the effects are counted whether or not debiased is True. With debiased=True, the unadjusted and robust standard errors are those of the regression that includes a dummy variable for each effect. The number of effects is the number of entities for entity effects, the number of time periods for time effects and the number of groups for each of the other effects. One is subtracted from the number of each of the effects after the first, and from the number of the first if the model has a constant, because the effects are not separately identified. Counting the effects is not needed when they are nested in the clusters, which is described next.

    Clustered Covariance with Fixed Effects¶

    When using clustered standard errors and entity effects, it is not necessary to adjust for estimated effects. PanelOLS attempts to detect when this is the case and automatically adjust the degree of freedom. This is done when the model has a single effect and every group of the effect is in one cluster, for example entity effects clustered by entity. The effects are counted in all other cases. This can be overridden by setting the fit option auto_df=False and then changing the value of count_effects.

    Estimated Effects¶

    estimated_effects in the results is the combined effect of all of the effects in the model. It is a DataFrame with one column, the sum of the entity, time and other effects of each observation, and the effects are not available separately. It is NaN for PooledOLS, FirstDifferenceOLS and FamaMacBeth, and 0 for a PanelOLS model without effects. It adds to fitted_values and idiosyncratic to give the dependent variable.

    The effects do not have standard errors or any other inference, since they are not estimated consistently when the number of time periods is fixed. The effect of an entity is estimated from its \(T\) observations, so the error does not shrink when the number of entities grows. In a simulation with \(T=5\) and 200, 2,000 and 20,000 entities, the standard deviation of the error of the estimated entity effects was 0.441, 0.452 and 0.445, which is close to \(\sigma/\sqrt{T}=0.447\), where \(\sigma=1\) is the standard deviation of the idiosyncratic shocks. If you need inference for the effects of a small number of entities, include the effects as dummy variables in the regression, for example in PooledOLS, and use the results for the parameters of the dummy variables.

    The estimated effects of RandomEffects are \(\hat{\theta}_i\) times the entity mean of \(y-x^{\prime}\hat{\beta}\), where \(\hat{\theta}_i = 1-\sqrt{\hat{\sigma}^2_\epsilon/(T_i\hat{\sigma}^2_u + \hat{\sigma}^2_\epsilon)}\) and \(\hat{\sigma}^2_u\) is the estimated variance of the random effect. The estimate is set to 0 if it is negative. Then \(\hat{\theta}_i=0\), the model is the same as pooled OLS, and all of the estimated effects are 0. This is a property of the data, not a bug: the variation between the entities is not larger than the idiosyncratic shocks imply. The Effects entry of variance_decomposition is 0 and theta is 0 in the results when this happens.

    Splitting Entity and Time Effects¶

    The sum of an entity effect and a time effect is exactly additive, so the two can be recovered from the combined effect, up to a constant that can be moved from one to the other. The function below regresses the estimated effects on a set of dummy variables for the entities and a set for the time periods, using sparse matrices. The fit is exact, also in an unbalanced panel. Compare the differences of the effects, or normalize them, for example by setting the first time effect to 0.

    import numpy as np
import pandas as pd
import statsmodels.api as sm
from scipy.sparse import csr_array, hstack
from scipy.sparse.linalg import lsqr

from linearmodels import PanelOLS
from linearmodels.datasets import wage_panel


def split_effects(res):
    effects = res.estimated_effects.iloc[:, 0]
    entity = pd.Categorical(effects.index.get_level_values(0))
    time = pd.Categorical(effects.index.get_level_values(1))

    def dummies(cat):
        n = len(cat)
        return csr_array(
            (np.ones(n), (np.arange(n), cat.codes)), shape=(n, len(cat.categories))
        )

    design = hstack([dummies(entity), dummies(time)]).tocsr()
    solution = lsqr(
        design, effects.to_numpy(), atol=1e-14, btol=1e-14, iter_lim=10000
    )[0]
    k = len(entity.categories)
    return (
        pd.Series(solution[:k], index=entity.categories),
        pd.Series(solution[k:], index=time.categories),
    )


data = wage_panel.load().set_index(["nr", "year"])
exog = sm.add_constant(data[["expersq"]])
mod = PanelOLS(data.lwage, exog, entity_effects=True, time_effects=True)
entity_effects, time_effects = split_effects(mod.fit())
time_effects - time_effects.iloc[0]

    AbsorbingLS or PanelOLS¶

    PanelOLS has up to two effects. It has the statistics of a panel estimator, and inference that matches Stata’s xtreg. AbsorbingLS can absorb any number of effects, and effects interacted with continuous variables, and it is designed for models with very many groups. It is not a panel estimator, and it reports the statistics of a regression. See Absorbing Least Squares for more.

    Aligning Inputs¶

    The rows of dependent, exog, weights, other_effects and the clusters used in covariance estimation are paired by position. To prevent a value from being attached to the wrong observation, an input that carries labels (a pandas Series or DataFrame, an xarray DataArray, or PanelData) must use the same labels, in the same order, as dependent. A ValueError is raised if the labels differ, for example when the values of a regressor have been reversed or sorted differently from the outcome. Reindex the input to the index of dependent to correct this.

    NumPy arrays do not have labels and are always paired by position. The same is true of a pandas object that only has a default index, 0, 1, …, n-1, (and default columns, if it is a DataFrame without a MultiIndex) since there are no labels to compare. Use to_numpy() to explicitly pair the values of any other pandas object by position.

    If dependent does not carry labels, for example if it is a NumPy array, the first of exog, weights and other_effects that carries labels is the reference instead. Each of the inputs after it that carries labels, and clusters, must use the same labels, in the same order, or a ValueError that names both inputs is raised. If none of the inputs carries labels, all of them are paired by position. A list or a tuple is accepted wherever an array is accepted for weights, clusters and other_effects. It does not carry labels.

    Weights can be provided in any of the following shapes, where nobs is the number of time periods and nentity is the number of entities.

    • A single weight for each observation, either as a 1-d array with nobs * nentity values or as a Series or DataFrame with the same MultiIndex as dependent.

    • A single weight for each time period, as a 1-d array or Series with nobs values. The weight is used for every entity.

    • A single weight for each entity, as a 1-d array or Series with nentity values. The weight is used for every time period.

    • A weight for each time period and entity, as a 2-d array or a DataFrame with nobs rows and nentity columns.

    Weights that are defined for each time period, for each entity or for each combination of the two are matched to the time periods and entities in the order that they first appear in dependent. This is the case even if the rows of dependent are not sorted by entity and then time. When these weights are a pandas object, the index (and columns) must contain the time periods and entities in this order.

    \(R^2\) definitions¶

    The \(R^2\) definitions are all designed so that the reported value will match the original model using the estimated parameters. This differs from other packages, such as Stata, which use a correlation based measure which ignores the estimated intercept (if included) and allows for affine adjustments to estimated parameters. The main reported \(R^2\) (rsquared in returned results) is always the \(R^2\) from the actual model fit, after adjusting the data for:

    • weights (all estimators)

    • effects (PanelOLS)

    • re-centering (RandomEffects)

    • within entity aggregation (BetweenOLS)

    • differencing (FirstDifferenceOLS)
